Work With AI Agents: Coordinating Multiple Coding Harnesses

Most developers now have several AI coding tools installed — a couple of CLIs, an IDE assistant, maybe a GUI agent or two. Each keeps its own config, its own memory, and its own idea of what the project is. TormentNexus gives them one control plane: shared memory, shared MCP routing, and a session bus so sessions can coordinate instead of colliding.

The session bus

Sessions register with a harness name, model, and role. A coordinator session can then assign a task to one worker, broadcast to all of them, poll inboxes, and collect reports when they finish. Acknowledgements are per-recipient, so a broadcast stays pending for peers that have not read it yet. The bus is backed by the local kernel, with the L1 scratchpad as a fallback when the kernel is briefly unavailable.

One config, every harness

Extensions for each harness install the same skills, hooks, and MCP configuration, and pin shell tools off in favor of parity tools when a model requires it. The result: start work in one harness, hand it off through the bus, and pick it up in another with the same memory and tools waiting.
