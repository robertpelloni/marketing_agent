Give AI a Memory: Persistent Context Across Every Session

Every new AI coding session starts from zero. The agent does not know which database you chose last week, why a migration was written the way it was, or that the staging server is the one box it must never restart. You re-explain, it re-discovers, and the work compounds far less than it should.

Three tiers, one vault

TormentNexus (the engine behind HyperNexus) stores memory locally in three tiers. The L1 scratchpad holds the active goal, objective, and handoff notes — small, fast, and loaded at session start. The L2 vector vault holds facts and observations searchable by meaning and by full-text index, so "what did we decide about billing?" finds the answer even when the wording differs. The L3 cold archive keeps older session transcripts compressed and searchable, so nothing is ever truly lost.

Recall before work

The workflow change is simple: before planning, the agent recalls. It loads the scratchpad goal, searches L2 for the topic at hand, and only then starts editing. Decisions, gotchas, and owner preferences survive model switches, harness switches, and reboots — because the memory belongs to your machine, not to a chat window.

Local-first, by default

The vault is SQLite on your disk. No memory leaves the machine unless you configure an upstream. That makes the system safe for proprietary code and useful offline: memory search, session bootstrap, and tool routing all run against the local kernel on 127.0.0.1:7778.
