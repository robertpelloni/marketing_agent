# MEMORY — Internal Architectural Observations & Runtime Knowledge

## Architecture & Framework Rules
- **Repository Identity**: `marketing_agent` (formerly `enterprise_sales_bot`), written in Go 1.25 modular monolith architecture with PostgreSQL for persistent state management.
- **Dual-Brand Split**: Dynamic routing between `hypernexus.site` (corporate/enterprise) and `tormentnexus.site` (open-source developers).
- **Single Page Dashboard Philosophy**: Keep the web dashboard consolidated on a single responsive view (`/`), avoiding scattered subpages and keeping high-value conversion indicators at the top (`/dashboard/outreach` 301-redirects to `/#outreach`; `/demo` remains the separate TormentNexus Cloud Console view).
- **Headless Unix vs Desktop Windows Systray**: Windows desktop runs `getlantern/systray` for taskbar notifications and interactive launchers (`cmd/marketing_agent/systray.go`). Unix/Linux runners operate headlessly in background mode under `systemd`.
- **Cadence Engine & Contact Hygiene Invariants (`v0.7.4`–`v0.7.7`)**:
  - Configured to `MaxAttempts: 10` across a monotonic 5-step multi-channel sequence (`intro-email` -> `github-hook` -> `followup-email` -> `linkedin-connect` -> `breakup-email`).
  - Always resolve cadence position from `TemplateID` + `Direction` (`Outbound` / `Skipped`), never `Channel` alone (since Steps 1, 3, and 5 share `email`).
  - Always execute channel delivery *before* persisting `Outbound` interactions or advancing `cadence_step`; record `Direction: "Skipped"` when an optional channel lacks a target so deals advance instead of stalling.
  - All enrichment sources and outbound email loops MUST filter addresses through `db.IsAutomatedOrUnroutableEmail` / `db.IsAutomatedCommitAuthor` (`internal/db/contact_hygiene.go`) and pick contacts via `db.SelectOutreachContact` so AI coding agents (`codex@openai.com`, `claude@anthropic.com`), CI bots (`bot@renovateapp.com`, `*[bot]*`), and non-MX domains (`*.github.io`, `*.local`) are never emailed, while human surnames ending in `bot` (`talbot`, `abbott`, `cabot`) remain allowed.
- **GitHub Public API Resilience & Queue Rotation (`v0.7.4`–`v0.7.7`)**:
  - Never gate `GitHubEnrichSource` on a non-empty `GITHUB_TOKEN`. On HTTP `401`, atomically mark the token invalid in memory and retry unauthenticated against public endpoints (`/repos/{owner}/{repo}/commits`, public search, public Actions runs) using HTTP/1.1 (`TLSNextProto: empty map`).
  - On HTTP `403`/`429` with `X-RateLimit-Remaining: 0` (or `"rate limit"`), immediately open the circuit breaker until `Retry-After` / `X-RateLimit-Reset` and return an error (`Failures++`), leaving unenriched deals untouched at the head of the queue.
  - On clean zero-contact outcomes (200/404/409 with only `noreply`/bot commits or `isGarbageLead`), call `TouchDealUpdatedAt` so `ListDealsForEnrichment` (`ORDER BY updated_at ASC`) rotates through the full `Discovered` backlog instead of re-checking the same 100 leads every hour.
  - `GitHubIssueSource` must use verified `/users/{owner}` profile websites or canonical `github.com/{owner}/{repo}` domains — never fabricate `<org>.com`/`.io` domains.
- **Researcher Caching & Target Hygiene (`v0.7.7`)**: `RSSFeedCrawler` caches parsed feeds in memory (`30m` TTL, `15m` backoff on `429`/`5xx`); `Researcher` skips deals with non-empty `TechnicalDossier` and strips raw email addresses / consumer webmail domains (`gmail.com`, `icloud.com`) before crawling.
- **Headless Browser Guardrail (`v0.7.4`)**: All `go-rod` launches (`LinkedInSource`, `LinkedInSender`) on shared 2-vCPU / 8 GB VPS hosts MUST enforce a 1-slot semaphore, `<=45s` hard timeout, `NoSandbox(true)`, `disable-dev-shm-usage`, and deferred `lnchr.Kill()` + `lnchr.Cleanup()` so Chromium never leaks processes or `/tmp/rod` user-data dirs.
