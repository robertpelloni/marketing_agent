Run LLMs Locally: An Offline-First AI Development Stack

Cloud models are powerful, but they come with rate limits, quota windows, and the occasional hard stop in the middle of a refactor. A local-first stack keeps the essential loop on your machine: local models for inference where they fit, local memory always, and a local kernel routing between the two.

What runs where

The TormentNexus kernel (Go, single binary) serves memory, tool routing, and session coordination on 127.0.0.1:7778. Local model servers plug in as providers alongside cloud ones, and a provider waterfall fails over in order — local first, cloud when a task needs more capability, next provider when one returns a rate limit instead of an answer.

Why local memory matters most

Even if inference goes to the cloud, your project memory should not have to. Decisions, handoffs, and session history live in local SQLite, searchable in milliseconds, and available on a plane with no Wi-Fi. When the cloud comes back, the agents pick up exactly where they left off.

What you give up, honestly

Frontier cloud models are still stronger on the hardest reasoning. The local-first answer is not "never use the cloud" — it is "never depend on it for memory, routing, or session state," and choose per task where inference happens.
