An AI Coding Workflow That Survives Restarts

Agent sessions end — quota, crash, context limit, or just the end of the day. A workflow that depends on one long-lived chat is fragile. The loop below is the one TormentNexus is built around, and it works in any harness:

1. Recall

Load the active goal and search memory for the topic before touching code. Most "agent mistakes" are really missing context that already existed somewhere.

2. Discover

Find the tools and code paths the task needs — progressively, not by dumping every tool schema and file into context. Search the repo graph, then read only the bodies that matter.

3. Execute

Make the smallest change that satisfies the requirement, in the harness best suited to it. Other sessions can work in parallel through the session bus without stepping on the same files.

4. Persist

Store what was learned — decisions, verification results, and the next step — back into memory, and update the handoff. This is the step that turns one session's work into the next session's head start.

5. Verify

Run the project's own tests and checks against the real code, and record the outcome. A result that was never observed is a guess, and guesses do not belong in the handoff.

Then the next session — yours, or another model's — starts at step 1 with everything intact. Download TormentNexus to run the loop locally.
